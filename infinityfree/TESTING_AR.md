# نتائج الاختبارات الأساسية

أُجريت الاختبارات محليًا باستخدام MariaDB 10.11 وخادم PHP 8.3 مع استيراد `schema.sql` و`seed.sql` في 23 أغسطس 2026. هذه النتائج توثق التحقق الفني، ولا تغني عن اختبار قبول المستخدم على حساب InfinityFree الفعلي.

| الاختبار | النتيجة | الدليل |
|---|---|---|
| استيراد المخطط وبيانات البداية | ناجح | أنشئ 43 جدولًا، و10 مقاطع مسار، وحجز وتذكرة أوليان |
| تسجيل دخول العميل | ناجح | أعاد الدور `customer` وصلاحيات الحجز الخاصة به |
| البحث عن رحلة صنعاء ← تعز | ناجح | أعاد الرحلة `NO-1001` والسعر بالمقطع الصحيح |
| حجز عميل قيد الانتظار | ناجح | أنشئ حجز بمقعد `1B` وبحالة `pending` |
| تأكيد مدير الشركة | ناجح | تغير الحجز إلى `confirmed` وأنشئت تذكرة |
| حجز وكيل وتأكيده | ناجح | أنشئ طلب وكيل ثم أكد إداريًا بنجاح |
| خصم محفظة الوكيل | ناجح | انخفض رصيد YER من 50,000 إلى 40,000 بعد تأكيد حجز 10,000 |
| احتساب العمولة | ناجح | سُجلت عمولة قابلة للصرف بقيمة 500 YER عند نسبة 5% |
| استخدام الائتمان | ناجح | بعد نفاد الرصيد، سُجل دين مستخدم بقيمة 10,000 YER وانخفض الائتمان المتاح إلى 10,000 YER |
| منع الائتمان المعطّل | ناجح | أعاد تأكيد حجز الوكيل حالة `409` ورمز `CREDIT_DISABLED` عند تعطيل الشراء الآجل |
| رفض الحجز | ناجح | رُفض طلب اختبار الائتمان وسُجل سبب الرفض بعد تصحيح استعلام PDO |
| انتهاء الحجز عند الطلب | ناجح | بعد جعل مهلة طلب قيد الانتظار منتهية، أدى طلب عرض المقاعد إلى تحويل الحالة إلى `expired` وتسجيل سبب تحرير المقاعد |
| إدارة البيانات المرجعية | ناجح | أنشأ المدير الرئيسي دولة ومدينة ومحطة وعملة وسعر صرف عبر API محمي |
| إدارة الأدوار | ناجح | تم تعيين دور ضمن شركة للمستخدم عبر مسار إداري مع سجل تدقيق |
| فهرس الإدارة | ناجح | أعاد فهرس المدير الرئيسي المستخدمين والأدوار والشركات والعملات لتغذية القوائم المفهومة في الواجهة |
| شحن محفظة وكيل | ناجح | سجل المدير الرئيسي شحن رصيد تجريبي لحساب الوكيل عبر المعاملة الإدارية |
| واجهة العميل | ناجح | ظهرت المدن والشركات والمسار من API بتصميم RTL متجاوب |
| لوحة المدير | ناجح | ظهرت مؤشرات الشركة والحجوزات ضمن الشركة فقط بعد الدخول |
| لوحة الوكيل | ناجح | ظهر الرصيد والحد الائتماني والدين المستخدم ضمن حساب الوكيل فقط |

## أوامر فحص سريعة

```bash
find . -name '*.php' -print0 | xargs -0 -n1 php -l
node --check assets/js/app.js
./testing/run_api_checks.sh
```

تتحقق مجموعة `run_api_checks.sh` آليًا من صحة API، ومنع الوكيل من بيانات الإدارة، ومنع حجز مقعد متداخل، ومن نطاق عرض محفظة الوكيل، ومن خصم الرصيد ثم استعمال الائتمان، ومن رمز `CREDIT_DISABLED`. يجب تشغيلها على قاعدة بيانات منشأة حديثًا من `schema.sql` و`seed.sql` لأنها تنشئ حجوزات اختبارية وتؤكدها أو ترفضها. يمكن تغيير رابط الخادم وحسابات الاختبار من متغيرات البيئة `API_BASE` و`ADMIN_EMAIL` و`AGENT_EMAIL` و`CUSTOMER_EMAIL`.

> ينبغي تنفيذ اختبارات قبول إضافية بعد النشر: تغيير كلمات مرور العرض، اختبار اتصال قاعدة الاستضافة، إنشاء حجز من هاتف، ثم التحقق من التذكرة الصادرة من شاشة مسح مستقلة.
