# تقرير إصلاح لوحة الإدارة

## الإصلاحات المنفذة

أُصلحت عملية فتح فورمي إضافة وتعديل الشركات، مع حماية فتح النافذة من الاستثناءات وإظهار رسالة واضحة بدل بقاء الواجهة فارغة. بقيت حقول خط العرض وخط الطول والخريطة الصغيرة وزر البحث موجودة، وأصبح `location_query` مستبعدًا من جسم طلب الحفظ حتى لا يُرسل إلى الخادم كبيان شركة.

أُضيف رابط favicon ديناميكي في رأس لوحة التحكم وصفحات الموقع العام، ويُقرأ من `site_settings.icon_path` مع مسار آمن ونسخة cache-busting. كما أُضيفت صفحة مستقلة باسم «رسائل اتصل بنا» إلى القائمة الجانبية، مع عرض الرسائل، نافذة عرض التفاصيل، وتغيير الحالة. صفحة الإعدادات أصبحت مخصصة لهوية الموقع وقنوات التواصل بدل تكرار جدول الرسائل داخلها.

## الاختبار المحلي

شُغّل خادم PHP محليًا على نسخة المشروع. فحصت صفحة الشركات باستخدام fixture محلي يستعمل app.js الحقيقي مع API غير مدمّر. فتح فورم الإضافة بنجاح وظهر معه 21 عنصر إدخال/تحكم، بما في ذلك الإحداثيات والخريطة والبحث. فُتح فورم التعديل بنجاح وظهر معه 21 عنصرًا، وظهرت الإحداثيات والخريطة وحقول الوسائط.

فُحصت صفحة الإعدادات محليًا، وظهرت معاينة الشعار والأيقونة ورابط رسائل اتصل بنا في القائمة. فُحصت صفحة الرسائل محليًا وظهرت رسالة اختبار مع أزرار العرض والحالة. نجحت اختبارات `entity-management.test.mjs` و`contact-management.test.mjs`، ونجحت فحوص `node --check` و`php -l` و`git diff --check`.

## الاختبار الحي بعد الرفع

تم رفع الملفات المصححة إلى InfinityFree. صفحة الإعدادات الحية ظهرت بعنوان «الإعدادات»، وظهر رابط القائمة «رسائل اتصل بنا». تحقق DOM من وجود favicon الحي بالمسار `/uploads/site/icon.png`، كما ظهرت معاينة الأيقونة بصورة صحيحة.

في صفحة الشركات الحية فُتح فورم الإضافة بنجاح وظهر فيه 21 عنصرًا، مع الخريطة وزر البحث. ثم فُتح فورم التعديل بنجاح وظهر فيه 21 عنصرًا، مع حقلي الإحداثيات والخريطة وزر البحث. لم يتم حفظ أي شركة أو تعديل بيانات حقيقية أثناء الاختبار.

صفحة الرسائل الحية فتحت بنجاح، وظهر فيها جدول الرسائل المستلمة. في وقت التحقق لم توجد رسائل في قاعدة البيانات، فظهر الجدول بحالة «لا توجد رسائل تواصل بعد» بدل شاشة بيضاء.
