
## التسجيل كعميل

تم اختيار مقعد V001 وفتح فورم البيانات الشخصية. أُدخلت بيانات مسافر اختبارية ثم ظهر تنبيه حفظ البيانات ونافذة تسجيل الدخول. تم التحول إلى «إنشاء حساب عميل جديد»، وتعبئة الاسم والهاتف والدولة اليمن والمدينة صنعاء والبريد وكلمة المرور الاختبارية. النقر الأول لم يغيّر الشاشة، فأُعيد إرسال النموذج عبر حدث submit للتحقق من النتيجة الفعلية.

## تصفح واختيار المقاعد

ظهرت بطاقات شركة المتصدر ببيانات حقيقية من قاعدة البيانات، ومنها المدينة معبر والوجهة جده، نوع الخدمة اقتصادي، وقت الحضور 07:53 مساءً، وقت المغادرة 08:23 مساءً، و20 مقعدًا متاحًا من 20. فتح زر الحجز رحلة TR-000002 ومخطط المقاعد، ثم تم اختيار V001 وتحدث الملخص إلى مقعد واحد بقيمة 50,000 ر.ي. فتح زر «إدخال بياناتي» فورم المسافر مع الحقول الثمانية المطلوبة.

## التسجيل

تم فتح التسجيل من نافذة الدخول وتعبئة بيانات عميل اختبارية واختيار اليمن/صنعاء. بقيت نافذة التسجيل ظاهرة بعد النقر الأول، ثم أُعيد إرسال submit للتحقق من السبب؛ لم تظهر رسالة خطأ في DOM حتى الآن.

## نتيجة API التسجيل

تم التقاط الاستجابة مباشرة من الخادم بعد إرسال نموذج التسجيل: HTTP 500 مع الرسالة `حدث خطأ غير متوقع في الخادم` ورمز `INTERNAL_SERVER_ERROR`. لم يظهر السبب التفصيلي للعميل، لذلك يلزم فحص سجل PHP/الخادم قبل متابعة الحجز.

## إصلاح التسجيل والمتابعة

اتضح أن تسجيل العميل كان يعيد HTTP 500 لأن دور `customer` غير موجود في قاعدة الاختبار. أُضيف الدور بصورة idempotent، ثم أُعيد التسجيل بنجاح. أُغلقت نافذة التسجيل، ظهر زر «فتح حسابي»، وبقيت بيانات المسافر محفوظة، وتحول الزر إلى «إرسال طلب الحجز».

## إرسال الحجز

بعد نجاح تسجيل العميل وظهور زر «إرسال طلب الحجز»، تم النقر عليه. بقيت الصفحة على فورم بيانات المسافر دون ظهور التذكرة أو رسالة نجاح؛ سيتم التقاط استجابة API المباشرة لتحديد سبب عدم الانتقال.

## نجاح الحجز والتذكرة

بعد إضافة permission `create_booking` لدور customer، نجح إرسال الحجز عبر API بحالة HTTP 201. أُنشئ الحجز الاختباري بالرقم `BK-2026-342092` للرحلة `TR-000002` والمقعد `V001` بقيمة 50,000 ر.ي وحالة «قيد الانتظار». ظهرت صفحة التذكرة بتفاصيل الرحلة والمسافر ورمز QR فعلي.

## حجوزات العميل

تم اختبار زر «عرض حجوزاتي» من صفحة التذكرة بالنقر المباشر على عنصر الزر. ستتم قراءة الحالة النهائية للتأكد من أن الحجز يظهر في قائمة العميل؛ لم يتم إلغاء الحجز قبل اكتمال هذا الفحص.

## الإلغاء والتنظيف

فُتح تفاصيل الحجز من قائمة حجوزاتي، ثم تم الضغط على «إلغاء الحجز». عادت القائمة وأظهرت الحالة «ملغاة»، ما يؤكد نجاح مسار الإلغاء كعميل. يلزم الآن التحقق من تحرير V001 وحذف العميل الاختباري، مع فحص زر الوضع الليلي في صفحة الحجوزات لأنه لم يتغير بصريًا بعد النقر الأول.

## الوضع الليلي

بعد تحديث app.js وإعادة تحميل إصدار customer-test-2، تم اختبار زر الوضع الليلي على صفحة العميل الرئيسية ونجح التبديل، مع بقاء البطاقات وحقول البحث مقروءة.
